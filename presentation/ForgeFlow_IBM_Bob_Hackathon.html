The problem

Generating a web app is fast. Proving that it works is still manual.

< 1 in 3

Infrastructure generated by two frontier models deployed successfully on the first attempt: 30.2% and 26.8% of tasks.

Zhang et al., arXiv:2506.05623 (2025)

1–3

Repair iterations deliver most of the gain. After that, a fix loop mostly spends tokens.

Kiecker et al., arXiv:2607.05197 (2026)
Arimbur, arXiv:2604.10508 (2026)

Less secure

Repeated rounds of AI self-refinement made code less secure in a controlled study. An open-ended fix loop adds risk.

Shukla et al., IEEE ISTAS (2025)

Today developers close that gap by hand: tests written after the code, CI logs pasted into a chat, fixes retried with no stopping rule, and a manual click-through of the live site.

How it works

Six stages. Enter, skip or revisit any of them.

Each stage keeps its own state

Status and versioned artifacts per stage. Nothing is overwritten.

Stale, never deleted

Refining requirements marks downstream work stale, and you decide what to redo.

Only two hard rules

Start from screenshots, a structured spec, or go straight to Build. The blue arcs are the only prerequisites.

The core contribution

A repair loop that knows when to stop

What the repair agent sees

  • The failing tests
  • Only the sources those tests exercise
  • The git diff since the last green run
  • The acceptance criterion each test checks

Stops at the first of

  • Regression guarda patch breaks a passing test
  • No-progress guardthe failing count stops shrinking
  • Iteration cap
  • Budget captokens and cost, per project

Then it escalates to a human.

The ID follows the app into production

Live-validation results carry the same criterion ID, so a failure on the deployed URL points back to the requirement it breaks.

How the link is made

Criteria are minted as ac-<12 hex>. Tests carry the ID in their title, and the result parser reads it back from each run.

Where IBM Bob fits

ForgeFlow automates the bounded part. IBM Bob takes over where it stops.

IBM Bob as our development partner

ForgeFlow is a real, multi-service codebase of about 800 files: a FastAPI control plane, a React PWA, Docker sandboxes and deploy adapters. During the hackathon we worked on it in IBM Bob IDE, using Bob 2.0's full-repository context to onboard, review and extend it. The repo ships AGENTS.md and .bob/rules/ so Bob loads our conventions in every session.

Who it's for

For people who ship web apps faster than they can verify them

Student and indie builders

Go from screenshots or a short spec to a tested, deployed full-stack app without building a test harness or a deploy pipeline.

Agencies and small product teams

Every client prototype ships with a test suite traced to its acceptance criteria and a live-validation report.

Teams adopting AI coding tools

Generated code is verified with a stopping rule, a cost record per project, and a human decision at the end.

Cost discipline is built in

Models are routed by role. A small model classifies and summarizes; the code model runs only for code, tests and repair. Token use and cost are recorded per project against a budget cap. When money is tight, ForgeFlow skips planning before it skips verification.

Architecture
